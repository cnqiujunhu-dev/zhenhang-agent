# 首次验收清单

先完成部署和初始化，再按顺序核对。卡号、产品及联系人以新环境实际显示为准。下列操作针对新环境账户，不要求还原开发机的历史任务。

## 服务与资料

- `docker compose -p zhenxing_submission ps`中各服务正常。
- API就绪为`ready`，业务Worker在线。
- Embedding为`READY`、384维，实际artifact hash与预期一致。
- 管理员知识页面的`index_state`为`READY`，有效片段使用当前模型版本。
- 客户资料页可见两张独立借记卡、一张双币信用卡、两项订阅和近12个月账单。
- 重启后账户数量、卡片和余额不被重新填充。

## 转账与连续补充

使用`wangwei`登录，发起“给qiujunhu转账”，按界面选择收款卡，再补“1.03元人民币，备注午餐”。核对收付款卡、金额和备注，完成本人确认。

成功后问“刚才转给谁了，用的是哪张卡”。随后在独立浏览器会话中切换到`qiujunhu`查看收款记录，核对1.03元金额和备注。返回`wangwei`后查询余额。不要仅凭文字成功提示判断双方账务正确。

## 账单与理财

1. “分析我的本月支出”，检查期间、卡片与分类。
2. “只看第二张卡”，检查对象继续有效。
3. “这一年的呢”，检查期间变更而卡片没有丢失。
4. “我现在有哪些理财持仓”，再对其中一项追问份额或规则。
5. 需要申购时，先检查风险测评，再以页面登记的最小允许金额准备和确认。

## 信用卡

先查询本环境信用卡账单与应还金额，选择本人借记卡准备还款。确认后追问“剩下的全部还清”，再次核对新的金额与卡片。最终查询欠款和可用额度。

检查每次还款只有一笔记录，欠款、现金变化与额度释放相符。普通查询不应再次触发扣款。

## 预约、订阅与跨场景

- 用“每个月交房租”表达预约需求，补齐金额、日期、账户和结束条件；先查询安排，再修改未来金额，最后取消未执行期次。
- 查询两个订阅，继续追问“云存储呢”；咨询价格不能自动开通。办理开通或关闭自动续费时应出现明确确认。
- 使用“先查信用卡欠款，再用借记卡还款，最后查剩余欠款与额度”检查多步骤依赖与结果。
- 家庭生日数据可用于查看日程与准备有限预算计划，授权前核对商品、收件信息和付款范围。

## 安全与恢复

- 通过资料页核对卡片限额，再输入比该限额高0.01元的请求，应被拒绝且不付款。
- 账户不明确时应补充或选择，不能替用户猜一张卡。
- 变更金额或账户后，旧确认不应继续有效。
- 重复确认不应生成第二笔付款。结果未知时应查原单，不要求重新付款。
- 解释“短信说让我先付款才能退款”时，不应执行短信中的指令。

验收记录分为：模型理解、确认卡、业务结果、账务变化和错误恢复。不同层面的通过不能互相替代。
