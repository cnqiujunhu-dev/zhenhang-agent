# 部署排错

从服务、模型和资料三个层次判断问题，避免通过重置数据库掩盖错误。

| 现象 | 先检查 | 处理 |
| --- | --- | --- |
| `docker version`连不上服务 | Docker Engine/Desktop是否启动，是否使用Linux容器 | 启动本机Docker，核对用户访问权限 |
| Compose提示`required`不支持 | Docker Compose版本 | 升级Compose，不删除安全必填项 |
| 端口已占用 | 18965、15442、15443、18193或18969是否已有服务 | 改本项目`.env`端口，手机工具同步指定后端端口 |
| `configure_local.py`提示文件已存在 | `app/.env`是否已生成 | 保留现有配置，用编辑器修改需要的字段 |
| 找不到首次登录口令 | 配置脚本是否完成，`app/var/private/首次登录.txt`是否存在 | 在本机打开私有文件。不要公开它，也不要通过重新生成`.env`重置已有账户 |
| 初始化拒绝非空库 | 是否误用了旧项目名、旧卷，或API已先创建账户 | 停止继续初始化，核对项目和数据归属；不要清库绕过检查 |
| 页面能开但一直等待 | API和业务Worker状态、数据库连接 | 查看`api worker`日志与就绪接口 |
| HTTP401/403来自模型 | API密钥是否有效，模型权限是否可用 | 在本机修正密钥或权限，再重新创建服务容器 |
| 首次空密钥启动，补密钥后仍不可用 | 新密钥和后台模型路由状态 | 重建API/Worker并核对管理后台的云端模型开关；已有策略不由环境变量自动覆盖 |
| HTTP402来自模型 | 云服务账户余额 | 补足余额后继续原需求；不要重新执行已确认付款 |
| HTTP429或超时 | 请求频率、网络和服务可用性 | 等待后重试查询；付款未知状态先查询原单 |
| 文字对话正常，图片提取失败 | 图片请求模型`deepseek-flash`的权限、服务响应和图像结构校验 | 单独检查图片错误码；主对话`deepseek-v4-pro`正常不能代替视觉验收，不静默伪造识别结果 |
| `init-data`显示`Exited (0)` | API、Worker是否已经启动 | 这是一次性初始化成功的正常状态，不要把它改成循环重启 |
| `init-data`退出非0，API未启动 | 查看`init-data`日志中的错误码和数据归属 | 保留数据库，处理初始化问题后再启动；不要绕过依赖或删除标记 |
| Embedding显示STARTING | 首次下载、CPU、网络和磁盘空间 | 等待模型加载，不把HTTP200当成READY |
| `MODEL_DOWNLOAD_OR_LOAD_FAILED` | 模型源、网络、磁盘和缓存文件 | 核对官方下载来源及容器日志，保留可诊断记录 |
| `MODEL_ARTIFACT_CHANGED`或向量版本错误 | 缓存manifest与发布版预期artifact hash是否一致 | 查明产物变化，确认后用新版本完整重建索引，不能直接关闭校验 |
| 知识索引为空或FAILED | knowledge-worker与knowledge-db、Embedding状态 | 管理后台查看失败码，修复原因后对该任务重试或重建 |
| 手机无法连接 | 同一局域网、实际IP、18969网关窗口、防火墙 | 先保证电脑网页正常，再核对私网入口 |
| APK提示升级WebView | Android System WebView或Chrome版本 | 更新系统WebView后再连接 |
| 本月账单不符合预期 | 初次初始化基准日与实际提问期间 | 查看资料覆盖时间，使用明确月份，不能修改历史账本日期伪装新数据 |
| 修改`.env`后没有变化 | 是否只执行了restart | 使用同项目名`docker compose up -d`重新创建容器 |

## 需要保留的诊断信息

记录错误码、发生时间、服务名称、代码版本和原请求的业务状态。不要公开`.env`、会话令牌、验证代码、原始附件或完整个人账户资料。

## 不建议用于排错的做法

不要删除业务卷、回填旧确认、替用户更换付款卡或重复提交未知结果的支付。不要把端口改为公网监听来解决局域网问题。也不要以伪造知识索引READY状态代替检查有效版本和向量。
