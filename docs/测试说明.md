# 测试说明

源码包含明确的行为测试选集及其导入依赖。测试使用临时数据，历史录屏、开发机数据库和云模型密钥不作为运行前提。分组见`app/tests/release-suites.json`，pytest默认只收集pyproject.toml列明的主文件。

## 安装测试依赖

从源码根目录运行：

```shell
python -m venv app/.venv
```

Windows PowerShell用`app\.venv\Scripts\Activate.ps1`激活；Linux/macOS用`source app/.venv/bin/activate`。然后运行：

```shell
python -m pip install --require-hashes -r app/requirements-dev.lock -r app/requirements-build.lock
python -m pip install --no-deps --no-build-isolation -e app
cd app
```

## 后端选集

```shell
python scripts/run_checks.py --suite bootstrap
python scripts/run_checks.py --suite security
python scripts/run_checks.py --suite core
```

| 选集 | 覆盖范围 |
|---|---|
| bootstrap | 新凭据、空库保护、完整数据、重跑不重置、失败回滚和匿名演示入口关闭 |
| security | 原话与实体来源、角色、确认、重放、附件、隐私、限额与恢复 |
| core | 六场景业务、账务、订阅条款、信用卡、预约、连续补充和知识任务 |

一次运行全部随包主用例用`python scripts/run_checks.py --suite all`。JUnit输出在`app/var/checks/`的独立时间目录。不同选集有重复用例，不能直接相加为新准确率。

运行器清空模型密钥、使用新临时SQLite并禁止外网。固定测试口令仅用于临时fixture，部署初始化使用随机凭据。Windows受限执行器若在asyncio socketpair处阻塞，需要允许本机进程通信，不应改业务断言。SQLite行为验证不代替PostgreSQL行锁测试，历史PG证据单列。

## 前端

另开终端，从源码根目录运行：

```shell
cd app/web
npm ci
npm run build
node --test tests/*.test.mjs
```

构建包含TypeScript检查。随包11个前端测试文件检查真实组件、确认、恢复和卡片呈现，依赖fixture一并提供。截图是否存在不作为业务通过条件。

## Android与网关

在mobile目录按BUILDING.md准备环境后运行：

```shell
python android-client/tests/run_offline_checks.py
python -m pytest android-client/tests/test_lan_gateway.py -q
```

这些检查不调用银行或云模型。首次准备SDK、依赖与模型权重需要联网。
